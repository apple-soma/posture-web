- 総合姿勢スコア：研究上の根拠がある基準値がCVAのみで、重み付けの根拠もない。根拠の薄い単一の数値が目立つと評価の信頼性を損なうため、項目別の判定だけにする。検証で「分かりにくい」という声が出たら再検討する。
- 再測定の通知：参加者が少数のため、運営から連絡する。
- 推移グラフ・長期の履歴表示：有料案の機能として後回し。

## 2. プロダクトのコンセプト

### 確定事項

- 姿勢改善アプリは、**人に寄り添い、生涯の生活を豊かにするためのアプリ**です。
- スマホで撮影した姿勢を数値で測り、基準値と比べて、今の状態とどこを改善すべきかを分かりやすく示す。
- 本人の悩み（気になる部位・悩みの種類・度合い）も踏まえて、優先すべき運動を提案する。
- 「測定 → 評価 → ヒアリング → 運動推薦 → 運動記録 → 再測定 → 改善確認 → 次の運動推薦」のサイクルを繰り返し、一度測って終わりにしない。
- 写真はスマホのブラウザ内で解析し、サーバーに送らない。
- 医療診断をしない。測定値だけで病気や原因を断定しない。強い痛みなどがある場合は医療機関への相談を促す。

### 設計上の考え方（推奨）

- 測定値は、撮影条件と測定誤差の範囲を踏まえて扱う。誤差より小さい変化を「改善」と表示しない。
- 評価の判定・スコア・運動推薦は、決まったルールで計算する（同じ入力なら同じ結果になる）。初期版では生成AIに判定させない。
- 基準値・スコアの計算式・推薦ルールにはバージョンを付け、どの版で計算した結果かを後から追えるようにする。

## 3. 利用者と利用シーン

初期ターゲット仮説：35〜50歳のデスクワーカー。肩や背中の張り、姿勢の崩れが気になるが、自分の姿勢がどうなっていて、どこを直せばよいか分からない人（第13章で検証）。

- 正面と側面から姿勢を撮影して、今の状態を数値で知りたい。
- 自分の姿勢と悩みに合った運動を知りたい。
- しばらく運動を続けた後に測り直して、どれだけ変わったか確かめたい。

## 4. 技術構成（確定）

| 役割 | 採用技術 | 備考 |
|---|---|---|
| 利用端末 | スマホのブラウザ | Webアプリ。ネイティブアプリは初期スコープ外 |
| Webアプリ本体 | Next.js | |
| 公開（ホスティング） | Vercel | |
| データ保存 | Supabase | ユーザー情報・測定結果・ヒアリング・運動記録など |
| 姿勢の解析 | MediaPipe（Pose Landmarker） | ブラウザ内で実行 |

### 処理の流れ

```
スマホカメラ（撮影ガイド付き）
  ↓
ブラウザ内の MediaPipe で人体ランドマークを検出
  ↓
ブラウザ内で姿勢の指標（角度・左右差など）を計算
  ↓
測定結果（数値）とランドマーク座標だけを Supabase に保存
  ※写真そのものはサーバーに送らない
```

### 技術上の注意

- MediaPipe Pose のランドマークは、耳・肩・肘・手首・股関節・膝・足首・かかと・つま先などで、**臨床で使う解剖学的な目印（第7頸椎、耳珠、上前腸骨棘など）とは一致しない**。CVA は、C7 をユーザーがタップで指定し、耳珠の代わりに MediaPipe の耳ランドマークを使う方式で算出する（既存実装）。耳ランドマークと耳珠のずれ、タップ位置のばらつきが誤差になる点を、基準値との比較時に考慮する（第6章）。
- 角度は画像平面上で計算する前提のため、カメラを体に対して正対・垂直に置くことが精度の前提になる。撮影ガイドで担保する。
- ランドマークごとの検出信頼度（visibility）を確認し、閾値未満なら撮り直しを促す。
- 写真を一時的に端末内に保持する場合も、サーバーへアップロードしない。比較用に写真を保存するかは未決（第12章）。
- Supabase は Row Level Security で本人のデータだけを読み書きできるようにする。

### 4.1 アカウント方式（2026-11-14 決定、MVP）

| 項目 | 決定内容 |
|---|---|
| 認証基盤 | Supabase Auth（データ保存と同じ Supabase にそろえ、RLS でログイン中のユーザーIDをそのまま使う） |
| ログイン方式 | メールアドレスに届く**6桁のワンタイムコード**を入力する。マジックリンク（リンクをタップする方式）は使わない |
| 登録 | 一般の新規登録を無効にし、**管理者が招待した人だけ**が使える |
| Google・Apple でのログイン | MVPには入れない。参加者の声を聞いて追加を判断する（Supabase は同じメールアドレスのアカウントをまとめて扱えるため、後から追加してもデータは分かれない） |
| メール送信 | 参加者が少ないうちは Supabase 標準の送信で試す。届かない・遅いなどの問題があれば独自の SMTP を設定する |
| 退会・データ削除 | MVPでは運営への依頼を受けて手作業で行う（8.1節）。方法を同意画面に書く |

**判断の理由**
- コード入力方式は、iPhone でホーム画面に追加したアプリと Safari の間でログイン状態が分かれる問題が起きにくい。
- Google ログインは、LINE などのアプリ内ブラウザから開くと Google の方針によりログインできない。招待を LINE で送る場面が多いため、MVPの基本の方式にしない。
- パスワードを覚えてもらう必要がない。

## 5. 機能要件

### 5.1 姿勢撮影
- 正面・側面から撮影する。既存実装では、それぞれ上半身と下半身に分けて撮影する。
- 撮影ガイドを表示する：スマホの置き方（高さ・距離・垂直）、立ち位置、全身が枠に収まる目安、明るさ、体の線が分かる服装。
- セルフタイマーで撮影できる。
- 目的：毎回できるだけ同じ条件で測定できるようにする。

### 5.2 姿勢測定
- 人体ランドマークを検出し、頭部・肩・骨盤・膝・足首などの位置を取得する。
- 指標を算出する（第6章）。
- 検出結果（ランドマーク）を写真に重ねて表示し、本人が検出位置を確認できるようにする。
- 検出信頼度が低い場合は測定結果として保存せず、撮り直しを促す。
- 目的：姿勢を感覚ではなく数値で把握する。

### 5.3 姿勢評価
- 各測定値を、研究論文・理学療法等で使われる基準値と比較する。
- 目安と比べた状態に分類し、指標ごとの言葉で表示する（9.1節）。
- 総合姿勢スコアを算出する（計算式は未決）。※MVPでは入れない（1.2節）。
- 目的：現在の姿勢状態と、どこを改善すべきかを分かりやすくする。

### 5.4 測定結果表示
- 測定値・基準値（出典付き）・前回との差・改善ポイントを表示する。
- 前回との差が測定誤差の範囲内なら「変化なし（誤差の範囲）」と表示する。
- 目的：本人が姿勢の状態と変化を理解できるようにする。

### 5.5 ヒアリング
- 気になる部位を選ぶ（複数選択）：首、肩、肩甲骨、背中、腰、骨盤など。
- 悩みの種類を選ぶ：凝り、痛み、重さ、動かしにくさ、見た目など。
- 気になる度合いを 0〜10 で記録する（0=気にならない、10=想像できる範囲で最もつらい）。
- 強い痛み・しびれ等の確認項目を含め、該当する場合は第5.12の注意表示へ進む。
- 目的：測定結果だけでなく、本人の悩みも踏まえて改善方法を決める。

### 5.6 運動推薦
- 姿勢評価の結果とヒアリング結果を組み合わせ、おすすめの運動を提案する。
- 運動方法（説明・図や動画）、回数、時間を表示する。
- 推薦は運動マスタ（第8章）と推薦ルールに基づいて決める。推薦理由（どの測定結果・悩みに対応するか）を表示する。
- 運動ごとに「こういう場合は行わない」という注意を持たせ、該当者には出さない。
- 目的：ユーザーごとに優先して取り組むべき運動を示す。

#### 5.6.1 MVPの運動・推薦ルール（2026-11-14 決定）

**監修**：専門家の監修を受けられないため、**監修なしで始める**。その代わり、運動を負担の小さいものに絞り、安全側のルールを置く。一般公開の前には、理学療法士などの専門家に運動の内容と判定の言葉（9.1節）の確認を受ける。

**運動の範囲**
- 首・肩のゆっくりした動き、呼吸、足踏みなど、負担の小さい種目に限る。
- 既存の12種目のうち、背骨を大きくひねる種目（`seated-twist`）と、腕を高く上げる種目（`wall-slide`）はMVPでは出さない。かかと上げ（`calf-raise`）は椅子や壁につかまって行う手順にする。
- 種目ごとに、手順・回数（または時間）・行わない条件を書き分ける。MVPは文章と簡単な図までとし、動画は作らない。
- すべての種目に「痛みや違和感が出たらすぐにやめる」「痛みのない範囲で動かす」を表示する。
- 運動の画面に「専門家の監修を受ける前の、一般的な運動の例です」と明記する。

**推薦ルール**
1. 注意が必要な症状（強い痛み、しびれ、けがの直後など）があれば、運動を出さず医療機関への相談を促す。
2. ヒアリングで「痛み」を選んだ部位、または痛みの程度が「痛みがある」以上の場合は、その部位を対象にした運動を出さず、呼吸と足踏みなど全身の軽い運動だけにする（監修がない間の安全側のルール）。
3. ヒアリングで度合いが高い部位を優先する。
4. 測定の判定がCVAの「頭が前に出ている」「頭がやや前に出ている」なら首まわり、骨盤の左右差が目安外なら骨盤まわりのテーマを加える。
5. 肩の左右差に対して、片側だけを動かす運動は出さない。肩・胸まわりの一般的な運動にとどめる（左右差の原因は人によって違い、写真だけでは判断できないため）。
6. 推薦理由として、どの悩み・どの測定結果に対応するかを表示する。
7. 推薦ルールには版を付ける（`recommendations.rule_version`）。

### 5.7 運動実施記録
- 実施した運動、回数・時間、実施日時を記録する。
- 継続日数・実施回数を表示する。
- 目的：運動を続けるための習慣化を支援する。

### 5.8 再測定
- 一定期間運動した後に、初回と同じ項目・同じ撮影条件で測定する。
- **MVPの間隔（2026-11-14 決定）**：週1回。初回のあと1週間後と2週間後に測る（合計3回）。参加者ごとに測定する曜日を決め、運営から連絡する。
  - 理由：検証期間が2〜3週間と短く、姿勢の変化が「変化あり」の最小差（6.3節）を超えないことも多いと考えられる。そのため、姿勢の変化そのものより「測り直しが続くか」「変化なしの結果がどう受け止められるか」を確かめることを重視し、測定の回数を増やす。再現性のデータも増える。
- 再測定の時期を通知で促す（通知方式は未決）。※MVPでは通知を入れず、運営から連絡する（1.2節）。
- 目的：運動によって姿勢が実際に変わったかを確認する。

### 5.9 改善比較
- 初回 → 現在の測定値を比較し、角度・距離・スコアの変化を表示する。
- グラフで経過を表示する。
- 誤差の範囲を超えた変化だけを「変化あり」として扱う。
- 「運動の効果で改善した」と因果を断定する表現は避け、「測定値がこれだけ変わった」と事実として示す。
- 目的：何がどれだけ変わったかを数字で実感できるようにする。

### 5.10 姿勢・運動履歴
- 過去の測定結果、運動の実施履歴、姿勢スコアの推移を保存・表示する。
- 目的：長期的な姿勢の変化を確認できるようにする。

### 5.11 改善サイクル
```
測定 → 評価 → ヒアリング → 運動推薦 → 運動記録 → 再測定 → 改善確認 → 次の運動推薦（→ 繰り返し）
```
- 再測定の結果をもとに、次の運動推薦を更新する。
- 目的：一度測って終わりではなく、継続的に姿勢を改善するサービスにする。

### 5.12 安全性・注意表示
- 医療診断ではないことを、初回利用時・結果画面で明示する。
- 強い痛み、しびれ、けがの直後などに該当する場合は、運動を推薦せず医療機関への相談を促す。
- 測定値だけで病気や原因を断定しない。
- 目的：姿勢評価と医療診断を明確に区別し、安全に使えるようにする。

## 6. 測定指標（MVP版、2026-11-14 決定）

MVPで採用する指標・計算方法・基準値。**基準値・目安はすべて仮の値**として扱い、`reference_values` に版（例：`v0.1-mvp`）を付けて保存する。角度はすべて画素座標（正規化座標×画像の幅・高さ）で計算する。

### 6.1 指標一覧

| 指標 | 撮影 | 計算方法（MediaPipe ランドマーク） | MVPでの扱い | 基準値・目安（仮） |
|---|---|---|---|---|
| CVA（頭蓋脊椎角） | 側面・上半身 | ユーザーがタップした C7 と、見えている側の耳ランドマークを結ぶ線と水平線のなす角（既存実装） | **判定する** | 50°以上／45.5°以上50°未満／45.5°未満の3段階。健康な成人の平均（約49°）を参考として併記 |
| 肩の傾き | 正面・上半身 | 左右の肩ランドマークを結ぶ線と水平線のなす角（既存実装） | **判定する（仮の目安）** | 絶対値3°以内を目安内。どちらが高いかは別に表示 |
| 骨盤の傾き | 正面（上半身の写真を使う） | 左右の股関節ランドマークを結ぶ線と水平線のなす角（既存実装） | **判定する（仮の目安）** | 絶対値3°以内を目安内。どちらが高いかは別に表示 |
| 体幹の左右の傾き【新規】 | 正面・上半身 | 両肩の中点と両股関節の中点を結ぶ線と鉛直線のなす角 | 表示・記録のみ | なし |
| 首の傾き【新規】 | 側面・上半身 | 肩の中点を通る鉛直線と、肩の中点→耳の中点の線のなす角（側面では見えている側の肩・耳を使う） | 表示・記録のみ | 参考値：男性13.6°±3.2、女性15.4°±3.3 |
| 体幹の前傾【新規】 | 側面・上半身 | 股関節の中点を通る鉛直線と、股関節の中点→肩の中点の線のなす角 | 表示・記録のみ | 参考値：男性2.3°±1.4、女性1.5°±1.1 |
| 側面の前後ずれ（耳・肩・股関節・膝・足首） | 側面 | 既存実装（股関節を通る垂直線からの正規化座標のずれ） | **表示をやめる** | — |

### 6.2 決定の理由と注意

- **CVA**：45.5°は Mostafaee et al. 2024（20〜50歳90名、写真による測定）で、軽度と中等度〜重度の前方頭位を見分けるカットオフとして報告された値。50°は臨床研究で前方頭位の有無の境目としてよく使われる値。健康な成人の平均は Zárate-Tejero et al. 2024（122名、Kinovea）で48.76°±6.77。この研究では、年齢が10歳上がるとCVAが1.6°小さくなると報告されている。
- **肩・骨盤の3°**：Roggio et al. 2024（Sensors。18〜30歳の健康な成人200名、スマホ撮影＋MediaPipe Pose）の値から作った。肩のラインは1.2°±0.7〜0.9、股関節のラインは男性1.2°±0.8、女性1.5°±1.0で、平均＋2SDがおよそ3°になる。研究上の判定基準ではなく、健康な若年成人のばらつきから作った**アプリ独自の仮の目安**であることを画面に明記する。
- **測定誤差との関係**：健康な人の肩・骨盤の左右差は1〜2°程度と小さく、MediaPipe の推定誤差が同じくらいの大きさになるおそれがある。**再現性の確認（第10章の1）で、同じ人を繰り返し測ったときのばらつきが3°に近ければ、肩・骨盤の判定をやめて表示のみに戻す。**
- **首の傾きとCVA**：首の傾きは C7 のタップなしで自動的に測れる。MVPでは両方を記録し、再現性の確認でばらつきの小さい方を、今後の頭部の主な指標にするか検討する。
- **側面の前後ずれ**：正規化座標のずれはカメラとの距離や画像の縦横比で値が変わり、比べられる基準もないため、角度で表す指標（首の傾き・体幹の前傾）に置き換える。ランドマーク座標は保存するので、あとから再計算できる。
- **対象年齢のずれ**：基準値の多くは20〜30代のデータで、想定するユーザー（35〜50歳）より若い。年齢による違いは検証で確認する。
- 基準値は「正常／異常」ではなく目安として扱い、出典と測定条件（立位、対象者、測定方法）を `reference_values` に記録し、アプリ内でも示す。
- 判定の言葉（3段階・2段階の呼び方）は9.1節。

### 6.3 「変化あり」とみなす最小の差（2026-11-14 決定）

**仮の値（MVPの開始時点）**。`reference_values` と同様に版を付けて管理する。

| 指標 | 仮の最小差 | 根拠 |
|---|---|---|
| CVA | 5° | スマホアプリでのCVA測定の最小検出変化が約5°と報告されている（6.4節） |
| 肩の傾き・骨盤の傾き | 2° | MediaPipeでの文献値は見つからなかった。健康な若年成人のばらつき（SD 約1°）の2倍とした暫定値 |
| 表示のみの指標（体幹の左右の傾き、首の傾き、体幹の前傾） | 判定しない | 前回との差の数値だけを表示する |

- 前回との差の絶対値が最小差より小さければ「変化なし（誤差の範囲）」と表示する。
- 最小差以上なら、差の数値と向き（例：「頭の位置が 6.2° 後ろへ」）を事実として表示し、運動の効果と断定しない（5.9節）。

**再現性の確認（第10章の1）の方法**

- 実施時期：検証参加者に使ってもらう前。
- 対象：開発者と身近な人、3〜5人。
- 手順：同じ日に3回、撮影をやり直して測る（スマホの設置・立ち位置からやり直す）。別の日にもう1回測る。CVAは C7 のタップも毎回やり直す。
- 計算：指標ごとに測定の標準誤差（SEM）を求め、95%の最小検出変化 **MDC95 = 1.96 × √2 × SEM** を正式な最小差とする。
- 結果の反映：
  - MDC95 で仮の最小差を置き換え、版を上げる。
  - 肩・骨盤のばらつきが判定の目安（3°）に近い場合は、肩・骨盤の判定をやめて表示のみにする（6.2節）。
  - 首の傾きと CVA のばらつきを比べ、頭部の主な指標を検討する（6.2節）。

## 8. データ設計

### 8.1 MVPで保存するデータ（2026-11-14 決定）

| 種類 | 保存する内容 |
|---|---|
| ユーザー | ID、メールアドレス（ログイン用）、年代・性別（任意入力） |
| 同意の記録 | 同意した日時、同意文の版 |
| 測定1回分 | 日時、4枚分（正面・側面 × 上半身・下半身）のランドマーク座標と検出信頼度、画像サイズ、C7のタップ位置、MediaPipe のモデルの版 |
| 指標ごとの値 | 測定値、判定区分（9.1節）、計算方法の版、基準値の版 |
| ヒアリング | 部位、悩みの種類、度合い（0〜10）、注意が必要な症状への回答 |
| 運動の推薦と記録 | 推薦した運動と理由、推薦ルールの版、実施日時、実施時間、完了か中止か、実施後の感想（楽／変わらない／少しつらい） |
| **保存しないもの** | 写真、映像、音声、自由記述 |

**扱いの決定事項**

1. **ランドマーク座標を保存する**：計算方法や基準値を変えたときに過去の測定を再計算できるようにするため、また再現性の確認に使うため。写真ほどではないが体の形が分かるデータであることを同意画面で説明する。
2. **年代・性別は任意で聞く**：参考値に男女差があり、CVAは年齢で変わるため、判定の参考と分析に使う。未入力でも測定・判定はできるようにする。
3. **運営が参加者のデータを見る**：RLSで参加者同士は互いのデータを見られないようにする。検証のため運営は Supabase の管理画面などから全員の測定値と記録を見る。このことを同意画面に明記する。
4. **保持期間と削除**：検証の終了時に、データを削除するか続けて使うかを本人に選んでもらう。退会時はその人のデータをすべて削除する。MVPでは削除は運営への依頼を受けて手作業で行い、その方法を同意画面に書く。

- ヒアリングの痛みの程度などは健康に関わる情報として扱い、目的・保存内容・閲覧者・削除方法を説明したうえで明示的な同意を取る。法的な扱いは公開前に専門家に確認する。
- MVPでは、正面・側面 × 上半身・下半身の4枚を1回の測定としてまとめて保存する。

### 8.2 テーブル案（既存スキーマ確認後に調整）

既存アプリがある場合は既存の命名規則・ID・認証方式に合わせる。以下は概念モデル。8.1節と食い違う場合は8.1節を優先する（例：`posture_sessions` は4枚をまとめた1回分とし、`view` は写真ごとの情報として持つ）。

#### `posture_sessions` — 測定1回分
- `id`, `user_id`
- `measured_at`
- `view`（front / side）
- `capture_notes`（撮影条件のメモ、任意）
- `model_name`, `model_version`（MediaPipe のモデルと版）
- `landmarks`（正規化座標 0〜1 と visibility の配列。写真は含めない）
- `overall_confidence`
- `created_at`

#### `posture_measurements` — 指標ごとの測定値
- `id`, `session_id`
- `metric_key`（例：`head_forward_angle`, `shoulder_tilt`）
- `value`, `unit`
- `algorithm_version`（計算方法の版）
- `reference_value_id`（比較に使った基準値）
- `category`（判定区分。`within` / `slightly_outside` / `outside` / `no_reference`（表示のみの指標）/ `unreliable`（測定不可）。9.1節）

#### `reference_values` — 基準値マスタ
- `id`, `metric_key`, `version`
- 判定の閾値（区分ごとの範囲）
- `source`（出典：論文名・著者・年・URL など）
- `conditions`（測定条件：立位/座位、対象者、測定方法）
- `notes`（スマホ写真への当てはめに関する注意）

#### `posture_scores` — 総合スコア
- `id`, `session_id`（正面・側面をまとめる単位は既存設計と相談）
- `score`, `score_version`（計算式の版）

#### `hearing_records` — ヒアリング
- `id`, `user_id`, `recorded_at`
- 項目ごと：`body_part`, `complaint_type`, `severity`（0〜10、nullable）
- `red_flags`（強い痛み・しびれ等への回答）

#### `exercises` — 運動マスタ
- `id`, `name`, `description`, 図や動画の参照
- `target_metrics` / `target_complaints`（対応する指標・悩み）
- 標準の回数・時間
- `contraindications`（行わない条件）
- `reviewed_by`（監修者。未定なら空）

#### `recommendations` — 推薦結果
- `id`, `user_id`, 起点となった `session_id` と `hearing_record_id`
- `exercise_id`, `reason`, `rule_version`, `created_at`

#### `exercise_logs` — 運動の実施記録
- `id`, `user_id`, `exercise_id`, `performed_at`
- `reps` / `sets` / `duration_seconds`（nullable）

#### データ上の原則
- 写真は保存しない（保存する方針に変える場合は、保存先・権限・削除方法を先に決める）。
- ランドマーク座標を残し、計算方法や基準値が変わっても測定値を再計算できるようにする。
- 計算結果には、使った計算方法・基準値・スコア式の版を記録する。
- 未入力（NULL）と 0 を区別する。
- タイムゾーンを明確にし、ユーザーの現地日付で集計する。
- アカウント削除時の削除範囲を決め、本人がデータを削除できるようにする。

## 9. 安全性・表現のルール

- 「診断」「治る」「治療」など医療を連想させる言葉を使わない。肩こり・腰痛などの改善効果を約束しない（薬機法・景品表示法などに触れるおそれ）。
- 判定の言葉（9.1節）と宣伝文句は、公開前に専門家に確認する。
- 基準値はアプリ内で出典を示し、「目安」であることを明記する。
- 運動推薦は、注意が必要な症状の回答と運動ごとの禁忌に基づいて絞り込む。
- 初期版では、写真を外部のAIサービスに送らない。

### 9.1 判定の言葉（2026-11-14 決定、MVP用の仮の文言）

「正常／異常」「改善推奨」のような善し悪しを決めつける言葉は使わず、**指標ごとに、目安と比べた状態を言葉で表す**。

**データ上の判定区分（共通キー）**

| キー | 意味 |
|---|---|
| `within` | 目安の範囲内 |
| `slightly_outside` | 目安からやや外れている（3段階の指標のみ） |
| `outside` | 目安から外れている |
| `no_reference` | 判定しない指標（表示・記録のみ） |
| `unreliable` | 測定できなかった（C7未指定、検出信頼度が低いなど） |

画面の言葉は指標ごとに持たせ、区分キーとは分けて管理する。言葉を変えても、保存済みのデータに影響しないようにする。

**画面の言葉（MVP）**

| 指標 | `within` | `slightly_outside` | `outside` |
|---|---|---|---|
| CVA | 目安の範囲 | 頭がやや前に出ている | 頭が前に出ている |
| 肩の傾き | 左右差は目安内 | — | 左右差が目安より大きい（右が高い／左が高い） |
| 骨盤の傾き | 左右差は目安内 | — | 左右差が目安より大きい（右が高い／左が高い） |

- `no_reference` の指標は判定の言葉を出さず、測定値と参考値だけを表示する。
- `unreliable` は「測定できませんでした」と理由・撮り直しの方法を表示する。
- 左右の表記は本人から見た左右（写真の左右ではない）で統一する。
- 色は赤を使わない。目安内は緑系、目安外は黄系の落ち着いた色で、目安との位置関係だけを示す。
- どの判定にも「研究の目安と比べた結果で、診断ではありません」という一文を添える。肩・骨盤には「健康な若い成人のばらつきから作ったアプリ独自の仮の目安」であることも示す。
- 公開前に専門家の確認を受ける前提は変えない。MVPは招待した参加者限定のため、この仮の文言で進める。

## 10. 開発優先順位

1.1節の既存実装と1.2節のMVP範囲を前提にした推奨順。差分の確認後に並べ替えてよい。

1. **測定の再現性の確認**：同じ人を同じ条件で繰り返し測り、各指標（C7 タップを含む）のばらつきを記録する。「変化あり」とみなす最小の差の根拠にする（方法は6.3節）。測定値を書き出せる仕組み（開発用の画面やファイル出力）があると進めやすい。
2. **測定値の保存（Supabase 導入）**：Supabase の導入、認証（4.1節）、測定結果とランドマークの保存、RLS。既存の `localStorage` の運動記録をどう移すかも提案する。
3. **測定の不足分**：第6章の新しい指標（体幹の左右の傾き、首の傾き、体幹の前傾）の追加と、側面の前後ずれの表示の停止。
4. **評価と結果表示の拡張**：前回との差（誤差の範囲内は「変化なし」）、判定の言葉の統一。総合姿勢スコアはMVP外（1.2節）。未使用の `lib/posture.ts` は残すか削除するかを提案する。
5. **ヒアリングの拡張**：悩みの種類と 0〜10 の度合い、注意が必要な症状の確認。
6. **運動記録の拡張**：Supabase への保存、継続日数。
7. **再測定・改善比較・履歴**：初回と最新の比較、簡単なグラフ、測定の一覧。再測定の通知はMVP外（1.2節）。
8. **安全性・注意表示**：初回の説明と同意画面。

## 11. 受け入れ条件のたたき台

- スマホのブラウザで正面・側面を撮影し、写真をサーバーに送らずに測定結果を保存できる。
- 検出信頼度が低い場合は保存せず、撮り直しを促す。
- 各指標について、測定値・基準値・出典・判定・前回との差が表示される。
- 前回との差が誤差の範囲内なら「変化なし」と表示される。
- ヒアリング結果と測定結果に応じて運動が推薦され、推薦理由が表示される。
- 注意が必要な症状に該当する場合は運動が推薦されず、医療機関への相談が促される。
- 運動の実施を記録し、継続日数が表示される。
- 初回と現在の比較がグラフで表示される。
- 測定値・判定・スコアに、使った計算方法・基準値・スコア式の版が記録されている。
- 本人以外が他人のデータを読めない（RLS）。運営が閲覧することは同意画面に明記されている。
- 実装着手前に既存コード調査と変更方針が提示されている。

## 13. 事業コンセプト・初期検証（仮説）

本章は事業化に向けた仮説と検証案であり、顧客ニーズ・価格受容性・効果が確認済みであることを意味しない。

### 13.1 提供価値

姿勢を数値で知り、自分に合う運動で改善し、その変化を数字で実感できること。測定・ヒアリング・運動推薦・再測定を一つのサイクルにつなげ、年齢や暮らしが変わっても姿勢を整え続けられる伴走型のサービスを目指す。医療診断はせず、セルフケアを支援する。

### 13.2 初期ターゲット仮説

35〜50歳のデスクワーカーで、肩や背中の張り、姿勢の崩れが気になっているが、自分の姿勢の状態と、何をすればよいかが分からない人。年齢や職種だけで固定せず、インタビューと利用状況から見直す。

### 13.3 差別化の仮説

- 研究や理学療法で使われる指標で姿勢を数値化し、基準値と並べて見せる。
- 測定値だけでなく本人の悩みを組み合わせて運動を選ぶ。
- 初回と現在を比べ、何がどれだけ変わったかを数字とグラフで示す。
- 写真をサーバーに送らない。

この違いが継続や支払いにつながるかは、検証で確かめる。競合アプリの調査は未実施。
